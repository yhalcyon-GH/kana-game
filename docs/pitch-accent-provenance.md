# Pitch-accent data provenance

`src/data/accents.ts` (`ACCENT_PATTERNS`) drives a small, deliberately
de-emphasized visual hint on Learn's word cards (`WordCard.tsx`'s
`AccentedKana`): a High/Low line drawn over a word's kana, aligned by mora.
It is an educational pronunciation *hint*, not the source of truth for
audio pronunciation — see "Relationship to audio" below.

## What this covers

- As of the 2026-09 commercial-release audit: 299 curriculum words, 298 of
  which have a pitch-accent entry.
- The 1 word without an entry is a single-mora word (no accent contrast is
  possible — pitch accent is a property of how pitch moves *across* morae,
  so a one-mora word has nothing to contrast). `scripts/checkAccentData.mjs`
  enforces this: single-mora words must NOT have an entry, and every
  multi-mora word MUST have one.
- Some words have documented accent *variants* in the underlying source
  data (regional/dialect/source disagreement). Where that happened, the
  table records one deliberately-chosen reading rather than every variant —
  see "How ambiguous entries were resolved" below for the exact method and
  `src/data/accents.ts`'s git history for the original per-word source
  breakdowns.

## How the table was originally built

The table was generated by `scripts/buildAccentData.mjs` (removed as of
this audit — see "Current status" below) from
[accentjiten.com](https://accentjiten.com)'s aggregated pitch-accent
dataset, which itself aggregates NHK, OJAD, Wiktionary, Wadoku, Kanjium,
and Kishimoto-Tsuneyo. This is not a Claude/AI guess: an LLM's training
memory of Japanese pitch accent is unreliable, and this project's rule
(`feedback_dont_guess_pitch_accent` memory) is to source pitch accent from
real reference data, never from memory.

### How ambiguous entries were resolved

Some words had more than one accent on record (dialect variation, or
different sources disagreeing). Each ambiguous case was resolved by hand,
using one of, in order:

1. **Kanji disambiguation** — where a word's kana has multiple unrelated
   readings (e.g. あめ = 雨 "rain" vs 飴 "candy"), the correct-meaning kanji
   was used to pick the matching source entry.
2. **Source consensus** — where even the correct-meaning kanji had more
   than one accent on record, the reading backed by the broader majority of
   independent sources was chosen over a lone outlier.
3. **User-supplied correction** — a small number of entries were
   deliberately corrected by the app's maintainer against their own
   pronunciation, overriding the dataset's majority (e.g. えいが/`HLL`,
   トースト/`LHHH`, ハロウィン/`HLLL` — see PR #208).
4. **Manual entries** — a few words have no accentjiten record at all
   (either genuinely absent, or present only under a differently-spelled
   variant of the same reading); these were supplied directly by the
   maintainer or derived from an explicitly-documented variant-spelling
   match in the source dataset.

The full per-word reasoning (including the specific source-count
breakdowns behind each consensus call) is preserved in
`src/data/accents.ts`'s and the removed `buildAccentData.mjs`'s git
history — nothing about that history has been hidden or rewritten by this
audit.

### Approved values verified this audit

Two entries with a known past discrepancy were specifically re-verified:

- ハロウィン (Halloween) — `HLLL` (corrected from an earlier `LHLL` by PR
  #208; re-confirmed here).
- みずをのむ (mizu wo nomu) — `LHHHL`.

All other current `ACCENT_PATTERNS` values were left exactly as they stood
going into this audit — this audit did **not** re-derive, re-score, or
"fix" any value by comparing against UniDic, Kanjium, or any other
reference on its own initiative, and did not accept a majority-vote
argument to change any existing value. The full 298-entry table is treated
as a canonical, user-reviewed baseline.

## Current status: static data, no active external dependency

As of this audit, `src/data/accents.ts` is a **static, checked-in table**.
The original `scripts/buildAccentData.mjs` generator — which fetched
accentjiten.com's dataset over the network and rewrote `accents.ts` on
every run — has been removed. The commercial release does not depend on
any external pitch-accent database, network fetch, or generation pipeline
at build time or runtime.

In its place, `scripts/checkAccentData.mjs` verifies the checked-in table
without any network access:

- every current curriculum word's coverage (single-mora words excluded,
  every multi-mora word present);
- no stale entries left over for words that no longer exist;
- every value is H/L-only and matches its word's real mora count;
- the approved entry count (298) has not silently changed;
- two known-history spot-check pins (ハロウィン, みずをのむ) match their
  approved values.

This intentionally makes it impossible for routine tooling (`npm run
verify`, CI, or a future contributor running "the accent script") to
silently overwrite the approved table from an external source again. Adding
a genuinely new word's accent going forward means sourcing it with the same
rigor as the existing entries (a real reference dataset, or the
maintainer's own verified pronunciation) and adding it to `accents.ts` by
hand — never guessed from memory, and never bulk-regenerated.

## Relationship to audio

This pitch-accent line is a **separate, visual educational hint** — it has
no effect on and is not derived from the app's spoken audio. Audio
pronunciation (kana readings, vocabulary, and reading prompts) comes from
recorded/synthesized voice clips under `public/audio/`, which this audit
did not touch. See the App's About page for what generates that audio.
