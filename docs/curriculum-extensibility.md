# Curriculum extensibility: adding katakana, sokuon, chōon, and yōon

**Status: design decided in conversation (2026-08-14/15). Four new categories — katakana, sokuon, chōon, and yōon — are implemented, see "Progress" below.** A fifth, 特殊音 (tokushuon, extended katakana loanword digraphs), was also built and shipped once, then **deliberately removed** at the user's explicit request ("特殊音は今回なくていいです。消してください。") once they'd had a chance to review the live content — it isn't needed for this curriculum right now. All of this still lives on the unmerged `feature/katakana` branch, awaiting review — none of it has been merged to `main`. **Any further category work beyond these four is a new decision, not something this doc already scoped or anticipated.** The open questions from the first draft of this doc have been resolved by the user directly; this version reflects those decisions.

**Update (2026-08-15), from the user's own teaching material:** the user shared two PDFs from their own Japanese class covering 促音/長音/拗音, and asked for three things reflected in "Progress" below: (1) 促音/長音 vocabulary rewritten to use their exact minimal-pair examples (with/without gemination or a long vowel shown side by side — おと/おっと, ビル/ビール, etc.); (2) a short English `explanation` on `ScriptCategory` (rendered on `CategoryRowsPage`) and `GojuonRow` (rendered on `LearnPage`'s word-list step) — 長音 in particular now has 6 rows, one per hiragana vowel-column spelling rule (+ a katakana review row), each with its own rule explanation, instead of one flat lesson; (3) 拗音 promoted to its own top-level page (`/youon`), since it has enough rows to deserve one — the site is now four pages (`/hiragana`, `/katakana`, `/youon`, `/other`), not three, with `/other` now down to just 促音+長音 now that 特殊音 is gone and 拗音 has moved out.

The standard 33-combination yōon set (11 consonant groups × ゃ/ゅ/ょ) for **both scripts**: 66 new `CHARACTERS` entries total (きゃ/きゅ/きょ...りゃ/りゅ/りょ hiragana + キャ/キュ/キョ...リャ/リュ/リョ katakana), 14 rows (7 per script, folding dakuten/handakuten into their base row's lesson exactly like ka-row/sa-row/ta-row/ha-row already do), ~85 vocabulary words total across both scripts. Two judgment calls, made and documented in code comments (`curriculum.ts`'s `YOUON_CATEGORY_ID` block, `words.ts`'s yōon header):
  - **Scope: both hiragana AND katakana yōon**, not hiragana-only — real Japanese distinguishes きゃ from キャ, and katakana yōon is everyday loanword vocabulary (キャンプ camp, ジュース juice, ミャンマー Myanmar), a different concept from 特殊音's extended combos (ファ/ティ/ヴ, sounds with no native mora at all) — the two must not be conflated.
  - **Row structure: one monotonic order sequence within the single `youon` category**, not two independent per-script sequences — the schema's `order` is scoped by `categoryId` alone, with no per-script sub-scoping, so two rows can't both claim order 0 inside one category without breaking `getNextRowId`/`getCumulativeCharacterIds`. All hiragana yōon rows go first, then all katakana yōon rows — mirroring how the rest of the curriculum already treats the two scripts as separate large blocks rather than interleaving them lesson-by-lesson. `dependsOnCategoryIds: ['hiragana', 'katakana']` (same as sokuon/chōon) means every row can draw on the FULL base pool of both scripts regardless of this order, so the split has no effect on which base characters are available — it's purely a teaching-sequence choice.

  - **Added (2026-08-15): Word Builder splits a combo character's 2 glyphs into 2 separate tiles.** Previously a yōon character like きゃ was one tray tile (matching its one `characterId`); now the learner places き and ゃ individually, per explicit request. `WordBuilderPage.tsx`'s tile model changed from "one tile per characterId" to "one tile per kana glyph" (`[...word.kana]` for the target, and each distractor character's kana similarly split) — this is purely an interaction/rendering change, `characters.ts`'s one-character-id-per-mora data model is untouched. See `TrayTile`'s comment and `App.test.tsx`'s "splits combo characters into individual glyph tiles" test.

  This is also where the "one kana glyph = one mora" issue the "Remaining structural note" below warned about actually landed, for real content. **Resolution: NOT a rendering-model fix (deferred, real, non-trivial, correctly out of scope) — verified the existing fallbacks are safe and left them as the answer.** `WordCard.tsx`'s `AccentedKana` already had a length-mismatch guard (`accent.length !== n` → plain kana, no accent line); `scripts/buildAccentData.mjs` independently drops any resolved accent entry whose length doesn't match its word's glyph count, so no yōon word ever gets a mismatched `ACCENT_PATTERNS` entry to begin with — the two guards compose correctly and no yōon word's accent line renders wrong, it just doesn't render at all. ## Decisions made

1. **特殊音 scope**: extended katakana combinations for loanword sounds (ファ/フィ/ウェ/ティ/ディ/ヴ...), distinct from standard yōon. Confirmed by the user. (Later built, shipped, then removed entirely — see "Progress" above.)
2. **Route/URL shape**: nested category routes, `/practice/:categoryId/:lessonId/...` (e.g. `/practice/hiragana/a-row`, `/practice/katakana/a-row`, `/practice/sokuon/...`). Chosen over keeping flat globally-unique row ids, specifically because it keeps future development smoother even though it means migrating every existing hiragana URL (`/practice/a-row` → `/practice/hiragana/a-row`) — an intentional, confirmed tradeoff, not an oversight.
3. **Learn/Practice flow differs by category, in two concrete styles** (not the vaguer "character-set vs. concept" split the first draft proposed):

   **`contrast-pairs` style — 促音 (sokuon) and 長音 (chōon):**
   - Learn = listen to **minimal-pair words** that isolate the rule, not a per-character flashcard sequence. User's own examples:
     - 促音: おと (oto) vs. おっと (otto)
     - 長音: おばさん (obasan) vs. おばあさん (obaasan); ビル (biru) vs. ビール (biiru) — note 長音 deliberately spans both scripts in one lesson, hiragana's vowel-repetition pattern *and* a review/reinforcement of katakana's ー (which was already taught fresh under カタカナ単音, not re-taught here).
   - Tracing is **word-level only** — no separate "trace this one new character in isolation" phase, even for 促音's っ (which is a genuine new glyph). **Implemented in `feature/sokuon`**: `TracingPage.tsx` now branches on `learnStyle` — `'contrast-pairs'` rows start the session directly in the `'words'` phase and check `words.length === 0` for the empty-state guard instead of `charPool.length === 0`, so this also already supports a future 長音 lesson with zero new characters of its own (see "Remaining structural note" below) without further changes.
   - Practice = today's four games **minus Kana Quiz** — confirmed explicitly ("長音と促音はKanaQuizはできないのでなくします"). Kana Quiz's "see an isolated character, pick its reading" premise doesn't fit a duration/rhythm rule. Listening, Kana Typing, and Word Builder all still operate on whole words and remain applicable. **Implemented in `feature/sokuon`**: `PracticeHubPage.tsx` filters the Kana Quiz card out for `'contrast-pairs'` rows, `KanaQuizPage.tsx` also redirects away from direct navigation to the route, and the Review scope (which mixes every taught category) filters `'contrast-pairs'` characters out of just its own Kana Quiz pool via `useCurriculum.ts`'s `isQuizzableCharacterId` — Word Builder's distractor-tile pool is untouched, since っ/ッ are still fine to see as tiles.

   **`character-set` style — 拗音 (yōon), 特殊音, and (by the same logic) カタカナ単音:**
   - Learn works exactly like existing hiragana rows today: flashcard through each new character, recap grid, then vocabulary built from them. Confirmed explicitly ("いままでのひらがなと同様に").
   - Practice = all four existing games, unchanged.

   This replaces the first draft's `kind: 'character-set' | 'concept'` with what's actually a cleaner split — every category has real new characters *except* possibly 長音 (see next point), so the distinguishing factor is the **Learn/Tracing shape** (per-character vs. per-contrast-word), not "has new characters or not."

## Remaining structural note: 長音 introduces zero new characters (confirmed)

促音 introduces one real new glyph (っ) — it needed a `CHARACTERS` entry, stroke data, `CONFUSABLE_PAIRS` (vs つ/ツ), like any other character, just taught via word contrast rather than solo flashcard (done in `feature/sokuon`). 長音 introduces **none**, confirmed when its content was actually written (`feature/chouon`): ー is already taught fresh under カタカナ単音 (it's part of learning katakana itself, not its own lesson), and hiragana's long vowels reuse existing vowel characters — 長音's own lesson only ever *reviews* ー, never introduces it. `chouon-row` is a row with `characterIds: []` — `TracingPage.tsx`'s early-return checks `words.length` instead of `charPool.length` for `'contrast-pairs'` rows specifically (see above), so this case was already handled with no code changes needed; `LearnPage.tsx`'s skip-to-step-B behavior doesn't depend on `characterIds` being non-empty either. See the "Progress" section above for the specific new test coverage this exercised.

## Proposed shape (updated)

```ts
type ScriptCategory = {
  id: string              // 'hiragana' | 'katakana' | 'sokuon' | 'chouon' | 'youon'
  label: string
  learnStyle: 'character-set' | 'contrast-pairs'
  explanation?: string    // IMPLEMENTED (2026-08-15), simpler than the LessonContent idea below:
                           // a short English paragraph, rendered on CategoryRowsPage above the
                           // category's own rows — see the "Update (2026-08-15)" note up top.
                           // GojuonRow also gained its own optional `explanation` for rule-specific
                           // detail at the row level (rendered on LearnPage) — see 長音's 6 rows.
}

// Generalizes GojuonRow -> not every lesson is a gojuon row anymore.
type Lesson = {
  id: string
  categoryId: string
  order: number
  label: string
  characterIds?: string[]  // new characters taught by this lesson, if any (empty/absent for
                            // a lesson like 長音 that introduces none)
  contrastWords?: string[] // word ids illustrating the rule, for contrast-pairs lessons —
                            // these words' OWN characterIds still resolve normally against
                            // CHARACTERS; this is just "which words does this lesson show"
}

type LessonContent = {
  explanation: string
  video?: { url: string; durationSec?: number }
}
```

**`LessonContent`/`content` above was never adopted** — `ScriptCategory.explanation?: string` (implemented 2026-08-15, see the type block above) covers the "brief English explanation" need directly with no wrapper type; a `video` field remains unimplemented and unscoped, revisit only if the user actually asks for video content.

**Not adopted, as of `feature/sokuon`**: the `Lesson`/`contrastWords` rename above was judged unnecessary once sokuon was actually implemented — `GojuonRow`/`AnchorWord` already cover a `'contrast-pairs'` row's needs as-is: `characterIds` still holds the row's new characters (just not flashcarded), and `WORDS_BY_ROW[row.id]` already IS "every word this row shows" for both Learn and Practice, exactly like a `'character-set'` row's step B — no separate `contrastWords` subset was needed. `sokuon-row`'s words are simply ordered as adjacent pairs/families in `words.ts` (おと next to おっと, etc.) to read as a minimal-pair sequence without a schema change. Revisit this if a future `'contrast-pairs'` category genuinely needs a word list that's LARGER than what a single Learn pass should show (not true for 促音).

**Resolved, as of `feature/youon`** (superseding the paragraph below, kept for history): pitch-accent rendering (`WordCard.tsx`'s `AccentedKana`, `accents.ts`) does assume one kana glyph = one mora = one accent position, and yōon (りゃ = 2 glyphs, 1 mora) does break that assumption — but the resolution was to verify the EXISTING fallback is safe rather than build a real mora-aware fix (judged correctly out of scope, see the "拗音" Progress entry above for the full reasoning and new test coverage). No yōon word shows an accent line; none render a wrong one either. The same "verify the fallback, don't build a real fix" resolution applied to `StrokeOrderAnimation.tsx`/`scripts/fetchStrokeData.ts` for the same underlying reason (yōon characters are the first multi-glyph `CHARACTERS` entries KanjiVG has no matching data for). A genuine mora-aware accent/stroke-data model is still real, non-trivial future work if the deliberately-absent accent line/stroke guide for yōon (and, later, 特殊音) content ever needs to become a filled-in one — nothing below assumes that's imminent.

~~Original first-draft note, now superseded above~~: pitch-accent rendering assumes one kana glyph = one mora = one accent position, which yōon will break; needs a real fix before any yōon word can show a correct accent line. (促音's っ is a full mora on its own, so this never affected sokuon's accent lines — `AccentedKana` already rendered them correctly.)

## Resolved: mastered badge for zero-new-character lessons

Decided: 長音-style lessons with no new characters of their own never show 🌟 mastered — "taught" (viewed once) is the only completion signal they get. No new accuracy-based mastery metric is introduced. Every other category (促音, 拗音, カタカナ) has real characters and uses the existing taught/mastered mechanism unchanged.
