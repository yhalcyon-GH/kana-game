# KanaGame learning loop

For non-trivial KanaGame work, before planning:
- Read `Learnings.md` and apply only the entries relevant to the current task.
- Treat learnings as prior evidence, not rigid rules; current user instructions, code/tests, and newer evidence win.
- Briefly mention the relevant learning(s) only when they materially affect the plan; do not produce a routine startup summary.

During and after work:
- Let Auto Memory capture useful local working knowledge naturally.
- Do not edit `Learnings.md` merely because a session occurred.
- Use `/update-learnings` when a reusable, project-level lesson is worth sharing and versioning.
- Use `/consolidate-learnings` for periodic cleanup or when raw observations become numerous or repetitive.
